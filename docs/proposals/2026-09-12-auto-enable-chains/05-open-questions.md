# 05 遗留与后续

## 放宽档位的路径

起步档 ≥ 5 个端点约 190 条链。跑稳一段时间后可按下面顺序放宽，每次只动一个参数并观察：

1. `min_endpoints` 5 → 3（候选面从 193 涨到 592，常驻端点约 2591，探针约 130 次每秒）；
2. `max_chains` 400 → 更高（只增不减意味着这是长期只会逼近的上限）；
3. 若确有需求，再单独讨论测试网白名单。

## 已知的长期问题

- **集合只会变大**：只增不减是用户明确要求，长期靠 `max_chains` 封顶与人工减法兜底。
  运维需要定期看后台里活跃端点为 0 的已开启链，决定是否取消开启。
- **块时间估算**：非配置链的确认深度与 tip TTL 走默认路径（64 块、2s），快链的 tip 最多 2s 陈旧。
  由探针观测 head 推进速率自动估块时间仍是候选优化项，本次不做。
- **目录质量**：chainlist 的 `status` 与 `tvl` 覆盖不足两成，规则只能当打分项用。
  若将来接入更可靠的链元数据源，可把它提为门槛。
