一句话：**做一个 Rust 实现的区块链节点 RPC 路由网关**，聚合 chainlist 上各链的公开 RPC 节点池，
对外暴露按 chainId 路由的统一 JSON-RPC 入口，免 API key、无单点限流。

## 用户定的四条硬指标

1. **单链扛住 10000 QPS**：必然依赖请求去重 + 响应缓存，公开节点池只承接缓存未命中。
2. **智能摘除限频节点**：识别 429、各家限频错误码、HTML 错误页、超时，把被限频的公共节点
   冷却摘除，恢复后自动回池。
3. **用户端无错误感知**：上游失败对调用方透明（failover / 重试 / hedging），只有全池耗尽才报错。
4. **链覆盖**：先用 ETH 和 Monad 跑通全流程，随后铺开主流链。

## 关键约束

- 公开节点质量参差（限频、2xx 返回 HTML、区块滞后、假数据），**默认上游不可信**。
- 不做规避第三方服务条款的事：不伪装 UA 绕封锁，不对单一节点激进重试，对单个公共端点设
  并发与频率上限，遇 429 退避换节点。
- 测试禁止访问外网：目录数据用内置样例，上游行为用本地 mock，压测也用本地 mock 上游。

## 协作模式（沿用至今）

主会话做仓库治理与方案拆解，调研交给 Grok 落到 `docs/research/`，实现交给独立 worktree 里的
maker 会话，checker 单轮对抗审查，主会话复核合入。

## 结果

Phase 1–4 交付并验收：8 链真实端到端、10k QPS 压测双跑、429 摘除与回池时间线复现、
用户可见错误为 0。
